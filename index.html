1. Security Checklist (10 Poin Utama)

Pastikan 10 poin ini selalu dicek sebelum aplikasi dirilis ke tahap produksi:

  • ✅ Validasi Input: Selalu validasi data yang masuk dari pengguna (panjang, format, tipe) di sisi server, bukan hanya di sisi klien.
  • ✅ Sanitasi Output: Bersihkan data sebelum ditampilkan ke layar untuk mencegah eksekusi skrip berbahaya.
  • ✅ Manajemen Rahasia: Jangan pernah menyimpan API Key, password, atau token di dalam kode (hardcode). Gunakan file .env.
  • ✅ Enkripsi Data Sensitif: Gunakan algoritma hashing yang kuat (misal: bcrypt) untuk menyimpan password. Jangan simpan password dalam plain text.
  • ✅ Koneksi Aman: Selalu gunakan HTTPS/TLS untuk mengenkripsi data yang berpindah antara klien dan server.
  • ✅ Prinsip Hak Akses Minimal: Berikan akses atau izin seminimal mungkin yang diperlukan oleh sistem atau pengguna untuk menjalankan fungsinya.
  • ✅ Manajemen Sesi Aman: Gunakan token yang aman (seperti JWT) dan atur cookies dengan flag HttpOnly dan Secure.
  • ✅ Pembaruan Dependensi: Rutin perbarui library atau framework (seperti package dari npm/pip) untuk menambal celah keamanan (patching).
  • ✅ Rate Limiting: Batasi jumlah permintaan dari satu IP dalam waktu tertentu untuk mencegah serangan Brute Force dan DDoS skala kecil.
  • ✅ Logging Tanpa Data Sensitif: Catat (log) aktivitas error atau akses, tetapi jangan pernah me-log data sensitif seperti password atau nomor kartu kredit.

2. Testing Strategy (Aplikasi Web Sederhana)

Rencana pengujian untuk aplikasi web (misalnya: Sistem Toko Online Sederhana dengan 3-tier architecture):

Tahapan Testing Fokus Pengujian Contoh Konkret
1. Unit Testing Menguji fungsi-fungsi kecil secara terisolasi. Memastikan fungsi hitungTotalHarga(harga, diskon) mengembalikan nilai matematis yang benar.
2. Integration Testing Menguji komunikasi antar modul/layanan. Mengecek apakah API Gateway berhasil mengirim data produk ke Backend dan menyimpannya di Database.
3. System/E2E Testing Menguji alur sistem secara keseluruhan dari sudut pandang user. Simulasi: User Login -> Tambah barang ke keranjang -> Checkout -> Berhasil.
4. Security Testing Mencari celah keamanan sebelum rilis. Mencoba memasukkan skrip <script>alert(1)</script> ke dalam form komentar untuk melihat apakah aplikasi kebal XSS.
💡 Tips Praktis: Otomatiskan Unit dan Integration Testing menggunakan CI/CD pipeline (seperti GitHub Actions) agar kode selalu diuji setiap kali ada commit baru.

3. Best Practices (Kode Aman & Reliable)

  1. Clean Code & Modularitas: Tulis fungsi yang hanya melakukan satu tugas (Single Responsibility). Ini memudahkan pencarian bug dan review kode.
  2. Gunakan Version Control (Git) dengan Benar: Selalu buat branch baru untuk setiap fitur atau perbaikan. Jangan langsung melakukan commit ke branch main.
  3. Terapkan DRY (Don't Repeat Yourself): Hindari menulis kode yang sama berulang kali. Jika ada logika berulang, jadikan sebuah fungsi atau kelas yang dapat dipanggil kembali.
  4. Graceful Error Handling: Tangani error dengan elegan. Tampilkan pesan yang ramah bagi pengguna, dan sembunyikan jejak error (stack trace) agar tidak dimanfaatkan oleh peretas.
  5. Peer Code Review: Sebelum menggabungkan (merge) kode, pastikan ada developer lain yang mereview untuk menemukan kesalahan logika atau celah keamanan yang terlewat.

4. Common Vulnerabilities (3 Kerentanan Umum)

Berikut adalah 3 celah keamanan yang paling sering ditemukan menurut standar OWASP beserta cara mencegahnya:

1. SQL Injection (SQLi)

Deskripsi: Penyerang menyisipkan perintah SQL berbahaya ke dalam input form untuk memanipulasi atau mencuri data dari database.

Contoh Serangan: Input username diisi dengan admin' OR '1'='1.

Pencegahan: Selalu gunakan Parameterized Queries atau ORM (Object-Relational Mapping).
Contoh (Python): Jangan gunakan f"SELECT * FROM users WHERE nama='{input}'". Gunakan parameter: cursor.execute("SELECT * FROM users WHERE nama=?", (input,)).

2. Cross-Site Scripting (XSS)

Deskripsi: Penyerang menyuntikkan skrip berbahaya (biasanya JavaScript) ke dalam halaman web yang dilihat oleh pengguna lain untuk mencuri sesi (cookies).

Pencegahan: Lakukan Output Encoding/Escaping sebelum menampilkan data dari database ke HTML. Gunakan library template bawaan framework (seperti Jinja2 atau React) yang secara otomatis melakukan escape pada variabel.

3. Broken Authentication

Deskripsi: Celah pada mekanisme login dan manajemen sesi yang memungkinkan penyerang mengambil alih akun pengguna (misal: menebak password default, atau mencuri ID sesi).

Pencegahan:

  • Terapkan kebijakan password yang kuat (minimal 8 karakter, kombinasi huruf & angka).
  • Gunakan Multi-Factor Authentication (MFA).
  • Hancurkan sesi (session destroy) secara otomatis saat user logout atau setelah periode tidak aktif (timeout).
